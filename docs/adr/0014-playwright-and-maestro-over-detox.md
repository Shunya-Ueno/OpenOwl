# ADR-0014: E2E は Web を Playwright、iOS ネイティブを Maestro で書き、Detox を採用しない

- **状態**: Accepted
- **日付**: 2026-08-23
- **フェーズ**: 6

## 背景

フェーズ 6 で E2E テストを導入する。本プロジェクトには次の制約がある。

- **モック禁止**。テストは実 Supabase・実 DeepSeek に接続する（[roadmap.md](../roadmap.md)）。
- **iOS が主戦場**だが、同一コードベースから Web/PWA も配信する。
- **UI はモバイル幅専用**でレイアウト分岐が存在しない（[ADR-0005](./0005-mobile-only-viewport.md)）。
- CI は GitHub Actions。macOS ランナーは Linux ランナーの 10 倍の従量単価。

「iOS が主戦場だから iOS の E2E を PR のゲートにすべきか」が主要な論点だった。

## 決定

1. **Web の E2E を Playwright で書き、PR のマージ条件にする。**
2. **iOS ネイティブの E2E を Maestro で書き、手動 + 週次で回す。** PR のゲートにはしない。
3. **Detox は採用しない。**
4. 両者のセレクタは `testID` に一本化する。

## 理由

### Web を PR ゲートに据えられる理由

`react-native-web` により、画面ロジック・状態管理・API アクセス層は
**Web と iOS で同じコードが動く**。加えてレイアウト分岐が設計上存在しないため
（ADR-0005）、モバイル幅のブラウザで確認できることと iOS で確認できることの差は小さい。
バックエンド（Edge Function・RLS・DeepSeek）に至ってはプラットフォームに依存しない。

結果として **iOS 固有として別途守るべきなのは `.native.ts` に分岐している 3 箇所だけ**になる:
Apple / Google のネイティブサインイン、SecureStore によるセッション永続化、
カスタムスキームのディープリンク。これらは頻繁に変更されるコードではなく、
PR ごとに検証する必要が薄い。

### Detox を採用しない理由

決め手は 2 つある。

1. **テストするバイナリが出荷するバイナリと同一でない。** Detox はグレーボックスで、
   ネイティブのテストライブラリをアプリにリンクする必要がある。
   「実物に接続する」ことを一貫して重視してきた本プロジェクトで、
   「実物ではないバイナリ」をテストするのは方針として筋が通らない。
2. **Sign in with Apple のシートを扱いづらい。** Apple のサインイン UI は
   アプリ外プロセスで表示される。Detox はアプリ内部に同期する仕組みを持つ分、
   アプリ外の UI に弱い。**MVP の認証要件の中心**がこれでは本末転倒である。

副次的に、Expo で使うには `expo prebuild` とカスタム dev client のビルドが前提となり、
`ios/` を `.gitignore` している本リポジトリでは CI で毎回生成することになる。

### Maestro を選ぶ理由

- **ブラックボックス**。出荷するのと同じ `.app` をそのまま起動して操作する。
- フローが YAML で、JS のテストホストを React Native のバージョンに追従させる必要がない。
- アプリ外のネイティブダイアログを扱える。
- `testID` が iOS の accessibility identifier になるため、Playwright とセレクタを共有できる。

### Playwright を選ぶ理由

- Linux ランナーで動く。macOS ランナーより桁違いに安く、速い。
- テスト対象が `expo export` の出力そのもので、**Vercel が配信するものと同一**。
- Service Worker、`localStorage`、レスポンスヘッダという Web 固有の関心事を直接検証できる。

## 検討したが採用しなかった案

| 案 | 却下理由 |
| --- | --- |
| Detox 単独 | Web を全く覆えないため、どのみち Web 用ツールが必要になる。上記 2 つの決め手も解消しない |
| Maestro 単独（iOS のみ、Web の E2E を書かない） | PR ごとの検証が macOS ランナー必須になり、遅く高い。Web/PWA が MVP の配信対象である以上、Web を無検証で出すことにもなる |
| Playwright 単独（iOS の E2E を書かない） | `.native.ts` の 3 箇所（特に Apple サインイン = 審査要件）が完全に無検証になる |
| Appium | 設定量が Maestro より大幅に多く、得られるものが本プロジェクトの規模では変わらない |
| Playwright で iOS Safari（WebKit）も回す | PWA としての iOS Safari 検証にはなるが、**ネイティブアプリの検証ではない**。§ の 3 箇所は覆えない |

## 結果 / 影響

- E2E から触る要素には `testID` を付ける。表示文言でセレクタを書かない
  （文言は変わるうえ、エラーメッセージはサーバー由来でクライアントの管理外）。
- `testID` の一覧は `frontend/e2e/testIds.ts` に集約する。Maestro の YAML からは
  import できないため文字列で書くが、参照先をコメントで示す。
- `frontend/src/**/*.native.ts` を変更した PR では、iOS の E2E を**手動で**回すことを
  運用ルールとする。CI で強制しない（fork PR で必ず落ちるため）。
- 見直しのトリガー: Web と iOS で挙動が食い違うバグが実際に発生したとき、
  または `.native.ts` の分岐が 3 箇所を大きく超えて増えたとき。
