# E2E テスト戦略

対象: `backend/tests/`（Edge Function の統合テスト）と `frontend/e2e/`（アプリの E2E）。
前提として、このプロジェクトは**モックを使いません**（[ADR-0006](../adr/0006-no-mocks-testing-policy.md)）。
すべてのテストが実際の Supabase と実際の Gemini API に接続します。

## テストの層

MVP のテストは2層だけにします。層を増やすより、**実際に壊れる境界**を厚く見ます。

| 層 | 置き場所 | 何を検証するか | 実行時間 | LLM コスト |
| --- | --- | --- | --- | --- |
| **統合テスト**（バックエンド） | `backend/tests/` | Edge Function の入出力契約、RLS、キャッシュ、レート制限 | 数十秒 | 小（後述） |
| **E2E**（アプリ） | `frontend/e2e/` | 実機/エミュレータ上のユーザー操作の通し確認 | 数分 | 小 |

**ユニットテストは書きません。** MVP のロジックはドメインの値オブジェクト（`WordText` / `WordInput`）と
薄いマッピングが中心で、これらは統合テストを通せば実行経路として必ず踏まれます。
純粋関数だけを切り出して個別に検証する価値が、維持コストを上回らないと判断しました。
再検討のトリガー: ドメイン層に分岐の多い計算（学習アルゴリズム、復習間隔など）が入ったとき。

## E2E ツールの選定: Maestro

[ADR-0011](../adr/0011-maestro-for-e2e.md) で決定。要点のみ再掲します。

- **アプリのコードを変更せずに書ける。** Maestro は YAML でフローを記述し、
  `testID`（設計時から付与済み）で要素を掴みます。Detox のようにビルド設定へ
  テスト用のフックを入れる必要がありません。
- **Expo との相性。** Development Build に対してそのまま実行できます。
- **読める。** フローが YAML なので、実装者以外でも「何を確認しているか」が追えます。

Detox は同期制御（アニメーション待ちの自動化）で優れますが、
MVP の画面はアニメーションをほとんど持たず、その利点が効きません。
一方でネイティブビルド設定の維持コストは確実に発生するため、採用しませんでした。

## 何をテストするか

### バックエンド統合テスト（`backend/tests/`）

| # | テスト | LLM 呼び出し | 意図 |
| --- | --- | --- | --- |
| 1 | RLS: 他ユーザーの `search_history` が見えない | なし | **認可の根幹**。ここが破れると全ユーザーの検索履歴が漏れる |
| 2 | RLS: `search_history` に INSERT できない | なし | レート制限を迂回されないことの確認 |
| 3 | RLS: `synonyms` に INSERT できない | なし | 辞書データの汚染防止 |
| 4 | RLS: 他人の `profiles` を UPDATE できない | なし | |
| 5 | RLS: anon では全テーブルが読めない | なし | |
| 6 | RLS: 自分の履歴は読める | なし | 拒否だけでなく許可も確認する（過剰に締めていないこと） |
| 7 | `generate-synonyms` 成功パス | **あり** | 契約（`docs/api-spec.md`）どおりの応答が返るか |
| 8 | 同じ単語の2回目が `source: "cache"` | なし（キャッシュ） | コスト削減の要が実際に効いているか |
| 9 | 不正な単語 → 400 `invalid_request` | なし | LLM に到達する前に弾いているか |
| 10 | 未認証 → 401 `unauthorized` | なし | |
| 11 | `POST`/`OPTIONS` 以外 → 405 | なし | |
| 12 | `OPTIONS` → 204 + CORS ヘッダ | なし | `verify_jwt = false` にした判断が効いているか |

**LLM を実際に呼ぶのは 7 だけ**です。テスト用の単語を固定し、
2回目以降の実行ではキャッシュが効くため、繰り返してもトークンを消費しません。
ただしそれでは「生成パス」が一度しか通らないため、
テストの前処理で**その単語の既存の生成結果を service role で削除**し、
毎回必ず新規生成を通します（これはモックではなく、テストデータの管理です）。

### アプリ E2E（`frontend/e2e/`）

| フロー | 内容 |
| --- | --- |
| `01-sign-in.yaml` | メール+パスワードでログインし、ホームに到達する |
| `02-generate-synonyms.yaml` | 単語を入力 → 生成 → 類義語リストが表示される |
| `03-invalid-input.yaml` | 不正な入力で**送信前に**インラインエラーが出る（課金しない経路） |
| `04-history.yaml` | 履歴タブに直前の検索が並び、詳細を開ける |
| `05-sign-out.yaml` | サインアウトしてログイン画面に戻る |

**Google / Apple ログインは E2E の対象外**です。外部の認証画面を自動操作することになり、
テストが Google/Apple 側の UI 変更で壊れます。これらは手動確認に委ねます
（[ADR-0011](../adr/0011-maestro-for-e2e.md) の「影響」を参照）。

**サインアップも E2E の対象外**です。メール確認が有効なため、
受信箱の操作が必要になります。代わりに、テスト用ユーザーを
**確認済みの状態で事前作成**するセットアップスクリプトを用意します
（`backend/tests/scripts/seed-e2e-user.ts`）。

## テストデータの扱い

テスト用 Supabase プロジェクトは本番と分離しますが、**テスト間では共有**されます。
そのため以下を守ります。

1. **各テストは自分でユーザーを作り、終了時に削除する。**
   ユーザーを消せば `on delete cascade` で `profiles` と `search_history` も消えます。
2. **`words` / `synonym_generations` / `synonyms` は消さない。**
   これらは辞書データであり、ユーザーに紐づきません。
   残しておくことでキャッシュが効き、次回以降のテストが安くなります。
   例外は上記の「生成パスを毎回通すための削除」だけです。
3. **メールアドレスは実行ごとに一意にする**（`e2e+<uuid>@example.com`）。
   同時実行や前回の残骸との衝突を避けるためです。

## コストの見積もりと制御

| 制御 | 内容 |
| --- | --- |
| LLM を呼ぶテストは1本だけ | 上記 7 のみ。他はキャッシュ・エラー経路 |
| E2E は毎プッシュでは回さない | PR と手動実行に限定（[`ci-pipeline.md`](./ci-pipeline.md)） |
| 1回の実行あたりの生成回数 | 統合テスト1回 + E2E 1回 = **最大2回**（E2E 側はキャッシュに当たることが多い） |
| レート制限との関係 | テストは毎回新しいユーザーを作るため、1日30回の上限には当たらない |

## 実行方法

```bash
# 準備（1回だけ）: テスト用プロジェクトの URL・キーと E2E アカウントを設定する
cd backend
cp .env.test.example .env.test

# バックエンド統合テスト
npm run test:integration         # backend/ から

# E2E（Maestro。事前に Development Build のインストールが必要）
npm run e2e:seed                 # backend/ から。テスト用ユーザーを作成（冪等）
cd ../frontend && npm run e2e    # Maestro のフローを実行
```

ルート直下からは `npm run test:integration` / `npm run e2e:seed` / `npm run e2e` で
同じことができます（どこから叩いても同じスクリプトに届くよう委譲してあります）。

> Maestro は必ず**ワークスペースルート（`frontend/e2e`）**を指定して実行します。
> `flows/` を直接指定すると `config.yaml` が読まれず `${APP_ID}` が未解決になります。

> **未検証の注意**: この作業環境には Deno・Supabase CLI・エミュレータのいずれもなく、
> **ここに書いたテストは一度も実行できていません**。
> 初回はローカルで通してから CI に載せてください。
